# نرم‌افزار حسابداری (Acc-Rust)

نرم‌افزار حسابداری دسکتاپ برای Windows با رابط کاربری HTML/CSS/JavaScript و هستهٔ Rust + SQLite (Tauri 2).

## وضعیت فعلی

نسخهٔ ۵ برنامه در مرحلهٔ تثبیت است: پنج گزارش اصلی و چهار صورت تکمیلی پیاده‌سازی
شده‌اند و طبقه‌بندی حساب‌ها از schema v13 تاریخچهٔ تاریخ‌دار دارد، اما خروجی رسمی
صورت‌های مالی تا تأیید مستقل حسابدار/حسابرس و اجرای موفق CI روی commit نهایی
«نیازمند تأیید» است. خلاصهٔ کامل قابلیت‌ها، موارد باز و موانع انتشار در
[`Docs/Project-Status.md`](Docs/Project-Status.md) نگهداری می‌شود.

## امکانات اصلی

- تعریف گروه حساب، حساب کل، معین و تفصیلی ۱ با پیمایش سلسله‌مراتبی
- ثبت، ویرایش، دائمی‌سازی و حذف سند حسابداری
- کنترل تراز، تاریخ شمسی، حساب‌های فعال و سال مالی باز
- طبقه‌بندی صورت‌های مالی در سطح هر حساب (سرفصل، حساب کاهنده و تفکیک بر اساس علامت) با اعتبارسنجی مقصد حساب کاهنده
- تاریخچهٔ تاریخ‌دار طبقه‌بندی حساب (schema v13) و انتخاب نسخهٔ معتبر در تاریخ گزارش برای گزارش‌های اصلی و تکمیلی
- پیش‌نمایش فقط‌خواندنی اثر تغییر گروه بر حساب‌های صریح/ارث‌برنده پیش از ذخیره
- گزارش‌های دفتر روزنامه، دفتر کل، تراز آزمایشی، صورت سود و زیان و ترازنامه
- چهار صورت تکمیلی: جریان وجوه نقد (روش غیرمستقیم)، تغییرات حقوق مالکانه، بهای تمام‌شده و تخصیص سود
- کنترل خودکار سلامت گزارش‌ها (تراز آزمایشی، حساب‌های بدون سرفصل، حساب کاهنده، ماندهٔ حساب‌های موقت، تطابق سند بستن، سند بدون سال مالی، تاریخ خارج از سال مالی و ردیف حل‌نشدهٔ سطح چهار) و مسدود شدن چاپ رسمی در صورت خطای Integrity
- بستن سال مالی، برگشت بستن و انتقال مانده به سال بعد
- ورود و خروجی Excel برای حساب‌ها و اسناد
- پشتیبان‌گیری، اعتبارسنجی فایل پشتیبان و بازیابی با نسخهٔ ایمنی
- گزارش رویدادها (audit log) و کنترل هم‌زمانی ویرایش

## پیش‌نیازها

- Windows 10/11
- [Node.js](https://nodejs.org/) 20 یا جدیدتر
- [Rust](https://rustup.rs/) با toolchain پایدار (حداقل نسخهٔ تعریف‌شده در `src-tauri/Cargo.toml`)
- WebView2 (در Windows 11 پیش‌نصب است)

## اجرای پروژه

```bat
npm ci
npm run dev
```

یا با اسکریپت‌های ویندوزی:

```bat
run.bat            :: ساخت debug و اجرا
run.bat release    :: ساخت release و اجرا
run.bat cleanup    :: پاک‌کردن کش ساخت
```

## ساخت نسخهٔ دسکتاپ

```bat
build.bat            :: exe قابل حمل (پیش‌فرض)
build.bat installer  :: exe + نصاب NSIS
build.bat all        :: exe + نصاب NSIS
```

معادل دستورهای npm:

```bat
npm run build
```

خروجی‌ها در `src-tauri/target/release/` و نصاب NSIS در
`src-tauri/target/release/bundle/nsis/` ساخته می‌شوند. اسکریپت `build.bat`
خروجی‌ها را در پوشهٔ `dist/` نیز کپی می‌کند.

## اجرای نسخهٔ وب محلی (فقط همین دستگاه)

ساده‌ترین راه در ویندوز، دوبار کلیک روی `run-web.bat` در پوشهٔ پروژه است. این
اسکریپت نسخهٔ وب را در صورت نیاز می‌سازد، سرور را اجرا می‌کند و اگر سرور از قبل
روشن باشد فقط مرورگر را باز می‌کند. برای ساخت و اجرای نسخهٔ release از
`run-web.bat release` استفاده کنید. بستن پنجرهٔ آن، سرور را متوقف می‌کند.

روش خط فرمان:

```bat
npm run dev:web
```

این دستور یک سرور loopback روی `http://127.0.0.1:4174/` بالا می‌آورد و همان
رابط کاربری و همان پایگاه دادهٔ SQLite نسخهٔ دسکتاپ را در مرورگر اجرا می‌کند.
نسخهٔ وب روی شبکه یا سرور منتشر نمی‌شود، احراز هویت ندارد و برای همین دستگاه
است. روی ویندوز، صفحه در حالت پنجرهٔ برنامهٔ Edge/Chrome (بدون نوار آدرس و
تب‌های مرورگر) باز می‌شود تا فقط تایتل‌بار ویندوز بماند. فرم‌های وب به‌جای
پنجرهٔ مرورگر، درون همان تب و با تایتل‌بار سفارشی برنامه باز می‌شوند. پس از هر
به‌روزرسانی، پنجرهٔ سرور را ببندید و `run-web.bat` را دوباره اجرا کنید تا تب
تازه با رابط جدید باز شود. نسخهٔ دسکتاپ و وب را هم‌زمان روی یک فایل پایگاه داده
اجرا نکنید.

دامنهٔ فاز فعلی، خواندن و ذخیرهٔ تنظیمات/حساب‌ها/سال‌های مالی/لیست اسناد/تراز
آزمایشی، ساخت، ویرایش، حذف و تغییر وضعیت سال مالی، بستن سال مالی و انتقال مانده
به سال بعد، ثبت/ویرایش/حذف سند همراه با انتقال ردیف، صفحات دفتر
روزنامه/دفتر کل/سود و زیان/ترازنامه، صورت‌های تکمیلی تغییرات حقوق
مالکانه/بهای تمام‌شده/تخصیص سود/جریان نقد، پیش‌نمایش چاپ آن‌ها، پشتیبان‌گیری و
بازیابی پایگاه داده از مرورگر، و ورود/خروجی اکسل حساب‌ها و اسناد است. فرمان‌های
مهاجرت سطح چهار قدیمی و پشتیبان‌گیری از مسیر دلخواه در این مرحله پشتیبانی
نمی‌شوند.
راهنمای کامل، تنظیمات محیطی و ساخت فایل اجرایی در
[`Docs/Local-Web-Mode.md`](Docs/Local-Web-Mode.md) آمده است.

## آزمون‌ها و بررسی کد

```bat
npm run check:js
npm run lint:js
npm test
npx playwright install chromium
npm run test:e2e
cargo build --manifest-path src-tauri/Cargo.toml
npm run test:smoke:windows
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --all-features
cargo test --manifest-path src-tauri/Cargo.toml
```

- `npm run check:js` صحت نحوی فایل‌های JavaScript را بررسی می‌کند.
- `npm run lint:js` تحلیل ایستای ESLint را روی UI، scripts و tests اجرا می‌کند؛
  قواعد `no-undef`، `no-unused-vars`، `no-unsanitized`، promise و core rules فعال‌اند.
- `npm test` آزمون‌های واحد فرانت‌اند و آزمون رگرسیون اتصال صفحات گزارش را با test runner داخلی Node اجرا می‌کند.
- `npm run test:e2e` آزمون‌های واقعی مرورگر را با Playwright و Chromium اجرا می‌کند.
  بار اول باید Chromium را با `npx playwright install chromium` نصب کرد. این آزمون‌ها
  رابط کاربری را روی یک سرور استاتیک محلی (`scripts/serve-ui.mjs`) باز می‌کنند و
  تعامل انتخابگر حساب، فرم تعریف حساب و چرخهٔ کامل سند (ساخت، ذخیره، بازکردن،
  دائمی‌سازی و حذف) را در DOM واقعی بررسی می‌کنند. بک‌اند Tauri در این آزمون‌ها با
  یک mock درون‌صفحه‌ای (`tests/e2e/mock-tauri.js`) شبیه‌سازی می‌شود؛ منطق واقعی
  بک‌اند همچنان با آزمون‌های Rust پوشش داده می‌شود.
- `npm run test:smoke:windows` روی build debug، برنامهٔ واقعی Tauri/WebView2 را اجرا
  می‌کند و ساخت SQLite در پوشهٔ موقت ایزوله را بررسی می‌کند. ابتدا باید build debug
  با `cargo build --manifest-path src-tauri/Cargo.toml` ساخته شود.
- آزمون‌های Rust شامل قواعد سند، سال مالی، گزارش‌ها، Excel، پشتیبان‌گیری و مهاجرت پایگاه داده هستند.

## ساختار مخزن

| مسیر | توضیح |
| --- | --- |
| `ui/` | رابط کاربری Tauri (HTML، CSS و JavaScript) |
| `src-tauri/src/commands/` | پل فرمان‌های Tauri بین UI و منطق Rust |
| `src-tauri/src/db/` | اتصال SQLite، schema، مهاجرت، سال مالی، پشتیبان‌گیری و حساب‌ها |
| `src-tauri/src/vouchers/` | اعتبارسنجی، ذخیره، حذف، انتقال و گزارش‌های سند |
| `src-tauri/src/report/` | قالب‌بندی و محاسبات گزارش‌های چاپی |
| `src-tauri/src/excel/` | ورود و خروجی Excel |
| `src-tauri/src/web/` | سرور Axum و پل فرمان‌های حالت وب محلی |
| `ui/web-bridge.js` | شبیه‌سازی حداقلی `window.__TAURI__` در مرورگر |
| `scripts/` | ابزارهای بررسی، آزمون و سرور استاتیک UI |
| `tests/` | آزمون‌های واحد فرانت‌اند (`tests/e2e/` آزمون‌های Playwright) |
| `Docs/` | مستندات جاری، سیاست‌ها و آرشیو بررسی‌ها |

## معماری

```text
HTML/CSS/JS (Tauri WebView)
        │  invoke(...)
        ▼
src-tauri/src/commands/*.rs
        │
        ▼
src-tauri/src/vouchers, db, report, excel
        │
        ▼
SQLite (فایل پایگاه دادهٔ کاربر)
```

رابط کاربری هیچ منطق حسابداری حساسی را به‌تنهایی تعیین نمی‌کند؛ اعتبارسنجی نهایی
حساب‌ها، تراز سند، تاریخ، سال مالی و دائمی‌بودن سند در Rust و triggerهای SQLite
انجام می‌شود.

## مدل حساب‌ها

- **گروه حساب**: دسته‌بندی بالای حساب‌ها (مثلاً دارایی، بدهی، درآمد، هزینه).
- **حساب کل** (سطح ۱): کد چهاررقمی.
- **حساب معین** (سطح ۲): فرزند مستقیم حساب کل.
- **تفصیلی ۱** (سطح ۳): فرزند مستقیم حساب معین و متعلق به همان گروه حساب.

هر ردیف سند یک حساب پایه (کل یا معین) و به‌صورت اختیاری یک تفصیلی ۱ دارد.
بک‌اند و trigger پایگاه داده بررسی می‌کنند که تفصیلی انتخاب‌شده فرزند مستقیم همان
معین و هم‌گروه با آن باشد.

## اسناد و سال مالی

- سند باید حداقل دو ردیف داشته باشد و مجموع بدهکار و بستانکار آن برابر باشد.
- مبلغ هر ردیف و تعداد ردیف‌ها محدودیت دارند.
- ثبت و ویرایش در سال مالی بسته یا نهایی‌شده مجاز نیست.
- سند دائمی و ردیف‌های آن با triggerهای SQLite در برابر تغییر و حذف محافظت می‌شوند.
- ویرایش هم‌زمان با `expected_updated_at` و ذخیرهٔ تکراری با کلید idempotency کنترل می‌شود.
- بازگشایی سال مالی نهایی‌شده نیازمند دلیل و تأیید صریح است و در audit log ثبت می‌شود.

## پشتیبان‌گیری و بازیابی

پیش از بازیابی، از پایگاه دادهٔ فعال یک نسخهٔ ایمنی ساخته می‌شود. فایل پشتیبان از
نظر سلامت SQLite، ساختار جداول، کلیدهای خارجی و اعتبار اطلاعات حسابداری بررسی
می‌شود. در صورت شکست بازیابی، برنامه تلاش می‌کند نسخهٔ قبلی را بازگرداند.
تعداد نسخه‌های پشتیبان نگهداری‌شده محدود است تا پوشهٔ پشتیبان بی‌رویه رشد نکند.
snapshotهای پیش از حذف گروهی و پیش از مهاجرت حساب‌های سطح ۴ نیز هر کدام جداگانه
نگهداری می‌شوند و فایل SQLite و manifest متناظر آن‌ها با هم حذف می‌شوند.

برای انتقال ایمن، «پشتیبان رمزنگاری‌شده» یک فایل `.hacc` می‌سازد که با رمز عبور
کاربر و الگوریتم AES-256-GCM محافظت می‌شود. کلید با Argon2id مشتق می‌شود و در فایل
ذخیره نمی‌شود. پارامترهای KDF در هدر فقط با ترکیب ثابت و مجاز نویسنده
(`19 MiB / t=2 / p=1`) پذیرفته می‌شوند و پیش از اجرای Argon2 بررسی می‌شوند؛ اندازهٔ
داده نیز حداکثر ۵۱۲ مگابایت است. هنگام بازیابی، رمز و یکپارچگی فایل پیش از
جایگزینی پایگاه داده بررسی می‌شود. پشتیبان‌های عادی قدیمی `.sqlite3`/`.db` همچنان
پشتیبانی می‌شوند.

## CI

workflow در `.github/workflows/ci.yml` چهار job دارد:

1. **verify**: نصب قطعی وابستگی‌ها با `npm ci`، بررسی نحوی JavaScript، lint با
   ESLint، آزمون‌های واحد فرانت‌اند، بررسی قالب‌بندی Rust، Clippy و آزمون‌های Rust.
2. **ui-e2e**: نصب Chromium و اجرای آزمون‌های واقعی مرورگر با Playwright؛ در صورت
   شکست، گزارش و trace آزمون‌ها به‌عنوان Artifact آپلود می‌شود.
3. **security-audit**: اجرای `npm audit --audit-level=moderate` و `cargo audit --deny warnings`.
4. **desktop-build**: فقط پس از موفقیت `verify`، `ui-e2e` و `security-audit` اجرا
   می‌شود. ساخت دو مرحله‌ای است: ابتدا `tauri build --no-bundle` فایل اجرایی را
   می‌سازد، در صورت وجود گواهی همان فایل اجرایی امضا می‌شود، سپس
   `tauri bundle --no-binary-patching` نصاب NSIS را از فایل امضاشده می‌سازد و در
   صورت وجود گواهی نصاب را نیز امضا می‌کند. در پایان `signtool verify /pa /v`
   اعتبار هر دو امضا را بررسی می‌کند. بدون گواهی، Artifact با نام
   `windows-build-unsigned` منتشر می‌شود؛ برای انتشار رسمی، اجرای
   `workflow_dispatch` با `release: true` در نبود گواهی یا رمز آن شکست می‌خورد و
   همهٔ فایل‌ها باید امضای Authenticode معتبر داشته باشند. انتشار رسمی همچنین به
   تأیید مستقل حسابدار در `Docs/Accounting-Report-Signoff.md` وابسته است. Artifact
   شامل فایل اجرایی مستقل `Hesabdari.exe`، نصاب NSIS، `release-metadata.json` و
   `SHA256SUMS.txt` است؛ metadata شامل hash، وضعیت واقعی امضا، اطلاعات گواهی و
   نشانهٔ `releaseBuild` است.
   Actionها با نسخه‌های سازگار Node 24 (`checkout@v7`، `setup-node@v7`،
   `upload-artifact@v7`) اجرا می‌شوند.

### Smoke test واقعی Windows/Tauri/WebView2

`desktop-build` پس از ساخت release، یک build debug نیز می‌سازد و
`node scripts/smoke-windows.mjs --exe src-tauri/target/debug/Hesabdari.exe` را
اجرا می‌کند. این تست برنامهٔ واقعی Tauri را اجرا می‌کند، ایجاد `msedgewebview2.exe`
را زیر فرایند برنامه بررسی می‌کند و انتظار دارد SQLite واقعی با هدر معتبر ساخته شود.
داده‌ها با متغیر `HESABDARI_SMOKE_DATA_DIR` به یک پوشهٔ موقت هدایت می‌شوند؛ این
override فقط در build debug فعال است، بنابراین release هرگز به دیتابیس کاربر متصل
نمی‌شود. پوشهٔ موقت پس از تست پاک می‌شود. تعامل کامل UI همچنان با Playwright mock و
آزمون‌های Rust پوشش داده می‌شود.
