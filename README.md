# نرم‌افزار حسابداری — نسخه ۵.۰

نرم‌افزار حسابداری رومیزی برای ویندوز، نوشته‌شده با Rust و Tauri، با رابط فارسی راست‌به‌چپ.
اطلاعات حساب‌ها و اسناد در یک پایگاه داده محلی SQLite نگهداری می‌شود و همه گزارش‌ها از
همان داده‌ها ساخته می‌شوند.

## فایل‌های آماده اجرا

| فایل | توضیح |
| --- | --- |
| `dist/Hesabdari.exe` | نسخه پرتابل (بدون نصب) |
| `dist/` | نصب‌کننده ویندوز (NSIS) پس از ساخت با گزینه `installer` یا `all` |

## اجرا

۱. فایل `Hesabdari.exe` را اجرا کنید (یا نصب‌کننده را نصب کنید).
۲. در صفحه «حساب‌ها» و «گروه‌های حساب»، ساختار حساب‌های شرکت را تعریف یا ویرایش کنید.
۳. از بخش «اسناد حسابداری» سند جدید بسازید؛ یا با `Ctrl+N` پنجره صدور سند را باز کنید.
۴. در پنجره سند، تاریخ و نوع سند را بررسی کنید، حساب‌ها را با `Space` یا `F4` انتخاب کنید،
   مبالغ بدهکار و بستانکار را وارد کنید و با `F2` ذخیره کنید.
۵. گزارش‌های دفتر روزنامه، دفتر کل، تراز آزمایشی، صورت سود و زیان و ترازنامه را ببینید و
   با دکمه «چاپ گزارش» پیش‌نمایش و چاپ کنید.

> سند فقط وقتی ذخیره می‌شود که حداقل دو ردیف داشته باشد، هر ردیف یک حساب قابل ثبت داشته باشد
> و جمع بدهکار با جمع بستانکار برابر باشد.

## امکانات

- ساختار کدینگ پس از گروه حساب شامل سه سطح «کل ← معین ← تفصیلی ۱» است. ایجاد سطح چهارم جدید و انتخاب آن برای سندهای جدید ممنوع است؛ رکوردهای تفصیلی ۲ قدیمی فقط برای سوابق قبلی حفظ می‌شوند و سندهای قدیمی با همان کد قابل ویرایش باقی می‌مانند.

- برنامه با «فضای کار» تمیز و بدون فهرست اسناد باز می‌شود؛ فهرست اسناد حسابداری در یک پنجره پاپ‌آپ مستقل، مشابه فرم صدور سند، باز می‌شود.
- تعریف گروه‌های حساب با نوع دارایی، بدهی، سرمایه، درآمد، هزینه یا سایر
- پنجره پاپ‌آپی مستقل برای تعریف و مرور حساب‌های کل، معین و تفصیلی ۱ زیرمجموعه گروه‌های حساب، با مسیر پیمایش، جست‌وجو، فیلتر، انتخاب، اصلاح و حذف امن
- ورود و خروجی اکسل کدینگ حساب با قالب ۱۱ ستونی سازگار با فایل‌های حساب‌های WebApp؛ ورود به‌ترتیب والد و فرزند انجام می‌شود و حساب‌های همسان موجود تکرار نمی‌شوند
- تعریف حساب‌های کل، معین و تفصیلی ۱ با کد، ماهیت، سرفصل بالاتر و قابلیت ثبت
- صدور، ویرایش، کپی، حذف و چاپ اسناد حسابداری (حداکثر مبلغ هر ردیف ۱۵ رقم)
- چهار نوع سند: عادی، افتتاحیه، اختتامیه و بستن حساب‌های موقت
- دفتر روزنامه و دفتر کل با مانده جاری و مانده افتتاحیه؛ دفتر کل حساب کل یا معین، گردش زیرحساب‌ها را هم جمع می‌کند
- تراز آزمایشی با گردش دوره و مانده پایان دوره
- صورت سود و زیان و ترازنامه با تشخیص خودکار طبقه حساب؛ سند بستن حساب‌های موقت در صورت سود و زیان و در محاسبات سود و زیان منظور نمی‌شود تا درآمد و هزینه دوره بسته‌شده صفر نمایش داده نشود، و ترازنامه بدون سند اختتامیه تهیه می‌شود
- جست‌وجوی اسناد با ارقام فارسی/انگلیسی و «ی/ک» عربی و فارسی؛ نویسه‌های % و _ به‌صورت معمولی جست‌وجو می‌شوند
- پیش‌نمایش چاپ A4 و ذخیره گزارش به‌صورت HTML
- تنظیمات نام شرکت و سال مالی

## محل نگهداری اطلاعات

پایگاه داده با نام `hesabdari.sqlite3` در پوشه داده برنامه در ویندوز
(`%APPDATA%\ir.hesabdari.software`) ساخته می‌شود. در نخستین اجرا، اگر پایگاه داده
نسخه قبلی (`audit-analyzer.sqlite3`) وجود داشته باشد، با دستور پشتیبان‌گیری سازگار با WAL
به‌صورت امن منتقل می‌شود. ساختار پایگاه داده نیز با مهاجرت‌های نسخه‌دار و افزایشی ارتقا می‌یابد؛
در صورت شکست انتقال، برنامه پایگاه داده خالی جایگزین نمی‌سازد و خطا را آشکار می‌کند.

## ساخت مجدد

### روش ساده (اسکریپت آماده)

فایل `build.bat` را در ریشه پروژه اجرا کنید:

```bat
build.bat              :: فقط exe پرتابل (پیش‌فرض)
build.bat portable     :: فقط exe پرتابل
build.bat all          :: exe پرتابل + نصب‌کننده NSIS
build.bat installer    :: فقط نصب‌کننده NSIS
build.bat clean        :: پاک کردن کش ساخت
```

خروجی پیش‌فرض `dist\Hesabdari.exe` (پرتابل) است و نصب‌کننده ساخته نمی‌شود.
اسکریپت کش ساخت (`CARGO_TARGET_DIR`) را داخل پوشه پروژه در `cargo-target\` قرار می‌دهد
تا همه خروجی‌های ساخت کنار سورس بمانند.

برای اجرای نسخه توسعه از `run.bat` استفاده کنید. هر بار اجرای این فایل، تغییرات سورس و
رابط کاربری را بررسی می‌کند، در صورت تغییر نسخه جدید می‌سازد، نسخه‌ای را که از همان مسیر
ساخت در حال اجراست می‌بندد و فایل اجرایی تازه را باز می‌کند. این روش hot reload هنگام
ویرایش نیست؛ پس از هر سری تغییر، `run.bat` را دوباره اجرا کنید:

```bat
run.bat            :: ساخت debug و اجرا
run.bat release    :: ساخت release و اجرا
run.bat cleanup    :: پاک کردن کش incremental پروفایل debug
```

### بررسی‌های خودکار

برای بررسی نحوی همه فایل‌های JavaScript رابط کاربری (بدون نصب وابستگی جدید) اجرا کنید:

```bash
npm run check:js
```

آزمون‌های واحد هسته Rust و منطق پایگاه داده نیز با ابزار زنجیره Rust اجرا می‌شوند:

```bash
cargo test --manifest-path src-tauri/Cargo.toml
```

`check:js` فقط خطاهای نحوی JavaScript را تشخیص می‌دهد و جایگزین آزمون یکپارچه رابط کاربری یا آزمون عملی روی Windows نیست.

### روش دستی

```powershell
$env:Path="$env:USERPROFILE\.cargo\bin;$env:Path"
$env:CARGO_TARGET_DIR="F:\GitHub\Acc-Rust\cargo-target"
cd F:\GitHub\Acc-Rust
cargo tauri build --no-bundle
```

خروجی: `F:\GitHub\Acc-Rust\cargo-target\release\Hesabdari.exe`

## ساختار پروژه

- `ui/` — رابط کاربری (HTML/CSS/JS، بدون باندلر)
- `src-tauri/src/db.rs` — پایگاه داده SQLite، جدول‌ها، حساب‌ها و تنظیمات
- `src-tauri/src/vouchers.rs` — ثبت اسناد و پرس‌وجوهای گزارش‌ها
- `src-tauri/src/report.rs` — ساخت گزارش‌های قابل چاپ A4
- `src-tauri/src/lib.rs` — فرمان‌های Tauri، پنجره‌ها و پیش‌نمایش چاپ


## به‌روزرسانی آزمایشی فرم سند حسابداری — 2026-11-02

این بسته قابلیت‌های زیر را برای فرم سند حسابداری Rust/Tauri اضافه می‌کند:

- کپی و انتقال ردیف‌های انتخابی به یک سند مقصد موجود یا سند جدید.
- شناسه پایدار دیتابیسی ردیف‌ها و اجرای انتقال در یک تراکنش SQLite.
- رد عملیات انتقال/کپی در صورت ناترازی ردیف‌های انتخابی، سند مقصد یا سند باقی‌مانده مبدأ.
- کپی و چسباندن ردیف‌ها از کلیپ‌بورد با ساختار جدولی سازگار با WebApp.
- فیلتر زنده ردیف‌ها بر اساس کد حساب، نام حساب، شرح و مبلغ.
- پیش‌نمایش دریافت اکسل، اعلام ردیف‌های معتبر و خطادار، و افزودن یا جایگزینی ردیف‌های معتبر.
- پیمایش سلسله‌مراتبی انتخابگر حساب با مسیر بالادست و امکان جستجوی مستقیم در کل فهرست.

محدودیت آگاهانه: مدل Rust فعلی فاقد وضعیت سند دائمی، قفل دوره مالی، نسخه‌گذاری هم‌زمانی (optimistic locking) و ثبت رویداد ممیزی معادل WebApp است. این بسته این مفاهیم را به‌صورت ظاهری شبیه‌سازی نمی‌کند و schema پایگاه داده را برای آن‌ها تغییر نمی‌دهد. انتقال ناتراز به‌صورت اجباری مجاز نیست.

پیش از جایگزینی فایل‌ها، از پایگاه داده SQLite پشتیبان تهیه کنید. build و اجرای Windows در این محیط انجام نشده است؛ بسته باید ابتدا در سیستم محلی کامپایل و آزمایش شود.
