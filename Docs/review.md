بررسی کردم، ولی کل پروژه (حدود ۳۱ هزار خط و ۱۳۲ فایل) رو نخوندم. روی بخش‌های پرریسک تمرکز کردم: راه‌اندازی دیتابیس و اسکیما، ذخیره و حذف اسناد، حذف گروهی، بازیابی پشتیبان، اتصال فرانت به بک‌اند و امنیت رندر در UI. گزارش‌ها، ایمپورت/اکسپورت اکسل و بیشتر صفحات UI و CSS رو بررسی نکردم. کامپایل و تست Rust اینجا ممکن نبود، اما تمام فایل‌های JS بدون خطای سینتکس هستند و ۴۸ فراخوانی invoke در فرانت همگی به کامندهای ثبت‌شده در بک‌اند وصل‌اند.

**مشکلات بک‌اند (به ترتیب اولویت)**
1. **مسیر دیتابیس اشتباهه و ریسک گم‌شدن داده داره.** کد دیتابیس رو کنار exe و در پوشه `database` می‌سازه، اما کامنت `.gitignore` می‌گه در AppData باشه. اگه exe رو به پوشه دیگه‌ای منتقل کنی یا از `dist` کپی کنی، برنامه دیتابیس خالی جدید می‌سازه و به نظر می‌رسه داده‌ها پاک شدن. همچنین اگه در Program Files نصب بشه، نوشتن روی فایل ممکنه خطا بده.

_راهکار:_ مسیر رو به `app_data_dir` برگردون (مهاجرت قدیمی رو نگه دار) و مسیر فعلی دیتابیس رو در تنظیمات نشون بده.

2. **همه کامندهای Tauri sync هستن و کارهای سنگین UI رو قفل می‌کنن.** بکاپ، ریستور، حذف گروهی، گزارش‌ها و ایمپورت اکسل روی ترد اصلی اجرا می‌شن و پنجره فریز می‌شه.

_راهکار:_ کامندهای سنگین رو `async` کن و داخلشون با `tauri::async_runtime::spawn_blocking` اجرا کن. اتصال Mutex هم نباید بین ترد UI و کارهای طولانی شریک باشه.

3. **حذف گروهی: فیلدهای** **`locked_count`** **و** **`locked_sample`** **همیشه صفر و خالی‌ان.** یعنی منطق قفل وجود نداره ولی UI ممکنه وانمود کنه که چیزی قفل شده. یا منطق قفل (مثلاً اسناد بسته‌شده در دوره مالی) رو پیاده کن، یا فیلدها رو حذف کن.

همچنین `DefaultHasher` بین نسخه‌های Rust پایدار نیست. برای توکن پیش‌نمایش در همین اجرا مشکلی نداره، ولی بهتره SHA-256 باشه تا رفتارش قابل پیش‌بینی بمونه.

4. **ثابت‌های تکراری.** `MAX_LINE_DESCRIPTION` و `MAX_AMOUNT` هم در `excel/common.rs` و هم در `vouchers/model.rs` تعریف شدن. `MAX_IMPORT_LINES` و `MAX_LINES` هم همین‌طورن. با تغییر یکی، اون یکی همراهش عوض نمی‌شه.

_راهکار:_ یه ماژول `limits.rs` بساز و همه‌جا ازش استفاده کن.

5. **کدهای گروه هاردکد شدن.** در `account_class_for_type_rule` گروه‌های `"10"` و `"11"` مستقیم نوشته شدن. این اعداد باید از متادیتای گروه یا یک جدول ثابت خونده بشن.
6. **پیام خطای ناخوانا.** در همان تابع، `query_row(...).map_err(db_error)` وقتی حساب پیدا نشه، خطای خام دیتابیس رو به کاربر نشون می‌ده. با `optional()` و پیام فارسی درست بشه.
7. **اعتبارسنجی N+1.** `validate_voucher_line_accounts` برای هر ردیف چند کوئری جدا می‌زنه. برای سند ۱۰۰۰ ردیفی بهتره کدهای حساب رو یک‌جا با `IN (...)` بگیری.
8. **تست‌ها.** ۱۱۶ تست Rust وجود داره. لطفاً `cargo test` رو بزن و خروجیش رو بفرست تا بررسی کنم.

**مشکلات فرانت‌اند**
1. **امنیت رندر.** در مواردی که بررسی کردم (`account-definition.js`، `account-groups.js`، `bulk-voucher-delete.js`، `menubar.js`) داده‌ها با `esc` escape می‌شن و هندلر inline هم نداری، پس CSP برای `script-src 'self'` مشکلی نداره. ولی تعداد `innerHTML` زیاده و escape کردن دستیه. پیشنهاد: یک helper مشترک (`esc` و `html`ی tagged template) در `utils.js` بذار و تابع `esc` رو که در ۴ فایل تکرار شده حذف کن.
2. **ساختار فایل‌ها آشفته‌ست.** `ui/` همزمان فایل‌های ریشه (`account-groups.js`، `account-definition.js`، `bulk-voucher-delete.js`، `print-preview.js`) و پوشه `js/` رو داره. `account-definition.js` داخل `index.html` لود می‌شه ولی یک صفحه جدا هم هست. `pages/accounts.js` و `account-definition.js` منطق مشابه دارن. قبل از هر چیز مشخص کن کدوم فایل‌ها زنده‌ان و کدوم مرده.
3. **استایل کد ناهمگون.** `account-definition.js` کاملاً فشرده و ریاضی‌وار نوشته شده، بقیه فایل‌ها تمیزتر. یه linter (ESLint) و Prettier کمک می‌کنه.
4. **اعداد و پول.** مبالغ به‌صورت INTEGER ریال ذخیره می‌شن که انتخاب درسته. سقف‌ها هم زیر `2^53` هستن، پس `Number()` در JS خطای دقت نمی‌ده.

**پیشنهادات برای کامل‌تر شدن برنامه**
*   **Soft delete یا سطل زباله برای اسناد**: الان حذف سند برگشت‌ناپذیره (فقط در حذف گروهی بکاپ داری).
*   **لاگ تغییرات**: الان فقط `updated_at` داری. جدول audit (چه کسی، کی، چی رو عوض کرد) برای حسابداری خیلی مهمه.
*   **بستن دوره مالی**: بعد از بستن، اسناد قبلی قفل بشن. این هم مشکل قفل‌شده‌های حذف گروهی رو حل می‌کنه.
*   **بکاپ خودکار** هنگام خروج یا هر N روز، با نگهداری آخرین N نسخه.
*   **هشدار تراز در لحظه** قبل از ذخیره، نه فقط بعد از خطا.
*   **میانبر صفحه‌کلید** برای ثبت سریع سند (Ctrl+S، ردیف جدید با Enter).
