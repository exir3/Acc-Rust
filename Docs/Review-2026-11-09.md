بررسی انجام شد و مخزن را با `git clone` گرفتم. حجمش حدود ۳۷ هزار خط Rust و ۱۵ هزار خط JS است و همه‌اش را نخواندم. `cargo` در محیط من نبود، پس کد Rust را کامپایل یا تست نکردم. بخش‌های JS را اجرا کردم: `check:js` و `lint:js` بدون خطا گذشتند، ۱۹ آزمون واحد قبول شد و `npm audit` صفر آسیب‌پذیری داد.

**آنچه خواندم:** `Cargo.toml`، `tauri.conf.json`، capabilities، `lib.rs`، لایهٔ commands، اتصال و مهاجرت پایگاه داده، رمزنگاری و پشتیبان‌گیری، بستن سال و انتقال مانده، اعتبارسنجی و ذخیرهٔ سند، جست‌وجو، خروجی Excel، الگوهای `innerHTML` در UI و `ci.yml`.

**آنچه عمیق نخواندم:** دقت عددی صورت‌های مالی، `integrity.rs`، پارس ایمپورت Excel، گرید سند و صفحهٔ تنظیمات.

موارد زیر را بررسی کردم و **مشکلی نداشتند**، پس در فهرست نیستند:
- قفل خوش‌بینانهٔ `updated_at` با دقت میلی‌ثانیه درست است.
- ۸۳ از ۸۷ دستور `async` هستند.
- فرار HTML (`esc`) منسجم است.
- خروجی Excel با `write_string` نوشته می‌شود، پس تزریق فرمول ندارد.
- رمزنگاری قطعه‌ای `.hacc` دقیق است.
- قاعدهٔ کبیسهٔ جلالی در JS و Rust یکسان است.
- در کد غیرتست فقط دو `unwrap/expect` هست.

## یافته‌ها

### اولویت بالا

**۱. پیش از مهاجرت schema نسخهٔ پشتیبان گرفته نمی‌شود**
- **محل:** `db/connection.rs`، تابع `initialize`.
- **مشکل:** `apply_schema_migrations` مستقیم روی دیتابیس واقعی اجرا می‌شود. تراکنشی است، ولی اگر مهاجرتی (مثلاً v13) با موفقیت اما با نتیجهٔ غلط تمام شود، راه برگشت نیست. نسخهٔ جدید دیتابیس را هم برای برنامهٔ قدیمی غیرقابل‌باز می‌کند. در کل مخزن چیزی مثل `pre-migration` پیدا نکردم.
- **راهکار:** قبل از مهاجرت، اگر نسخهٔ ذخیره‌شده از `CURRENT_SCHEMA_VERSION` کمتر بود، یک کپی بگیرید:
```rust
// بعد از Connection::open و پیش از apply_schema_migrations
let stored: i64 = connection
    .query_row("SELECT value FROM app_meta WHERE key='schema_version'", [],
               |r| r.get::<_, String>(0))
    .ok().and_then(|v| v.parse().ok()).unwrap_or(0);
if stored > 0 && stored < CURRENT_SCHEMA_VERSION {
    let snap = path.with_file_name(format!("before-migrate-v{stored}-{}.sqlite3", stamp));
    connection.execute("VACUUM INTO ?1", [snap.to_string_lossy().as_ref()])?;
}
```
نگه‌داری ۳ نسخهٔ آخر کافی است. بعد از مهاجرت هم `PRAGMA integrity_check` و `foreign_key_check` اجرا کنید (در بک‌لاگ خودتان هست).

**۲. برگشت بستن سال، سند افتتاحیهٔ سال بعد را بررسی نمی‌کند**
- **محل:** `db/closing.rs`، تابع `reverse_closing`.
- **مشکل:** فقط وضعیت اجرای بستن و `final` نبودن سال چک می‌شود. اگر مانده قبلاً به سال بعد منتقل شده باشد، بعد از برگشت و ویرایش اسناد سال قبل، افتتاحیهٔ سال بعد بی‌صدا کهنه می‌ماند. این همان P2-05 است، ولی گارد ساده‌ای در همین تابع هم لازم است.
- **راهکار:**
```rust
if let Some(next) = next_year(&tx, &year)? {
    if target_opening_voucher(&tx, &next)?.is_some() {
        return Err("برای سال بعد سند افتتاحیه صادر شده؛ ابتدا آن را حذف کنید یا تأیید صریح بدهید.".into());
    }
}
```
علاوه بر آن، یک کنترل Integrity بگذارید که مجموع افتتاحیه را با مانده‌های اختتامیهٔ سال قبل مقایسه کند.

**۳. شمارهٔ سند در کل پایگاه یکتاست، نه برای هر سال مالی**
- **محل:** `db/schema.rs` (ستون `number INTEGER NOT NULL UNIQUE`) و `MAX(number)+1` در `storage.rs` و `closing.rs`.
- **مشکل:** سند افتتاحیهٔ سال جدید شمارهٔ مثلاً ۱۳۴۰ می‌گیرد. در عرف حسابداری ایران معمولاً شماره‌گذاری هر سال از ۱ شروع می‌شود و افتتاحیه شمارهٔ ۱ است. اگر عمداً شمارهٔ سراسری می‌خواهید، این مورد را نادیده بگیرید.
- **راهکار:** با مهاجرت، `UNIQUE(fiscal_year_id, number)` بگذارید (نیاز به بازسازی جدول). شمارهٔ بعدی و `adjacent_voucher_number` را بر اساس سال مالی حساب کنید.

**۴. نرمال‌سازی «ی/ک» فقط هنگام جست‌وجو انجام می‌شود، نه هنگام ذخیره**
- **محل:** `db/validation.rs` (تابع `validate_name`) و `vouchers/query.rs`.
- **مشکل:** `validate_name` فقط فاصله‌ها را یکی می‌کند. جست‌وجو عبارت تایپ‌شده را نرمال می‌کند، ولی با نام ذخیره‌شده خام مقایسه می‌کند. فایل‌های Excel و خروجی نرم‌افزارهای قدیمی اغلب «ي» و «ك» عربی دارند. بنابراین نام ذخیره‌شده با «ي» عربی با جست‌وجوی فارسی پیدا نمی‌شود. دو حساب هم‌نام ظاهری هم می‌توانند جدا ثبت شوند.
- **راهکار:** یک تابع مرکزی بنویسید و در همهٔ مسیرهای نوشتن (نام حساب و گروه، شرح سند، ایمپورت Excel) صدا بزنید:
```rust
pub fn normalize_fa_text(s: &str) -> String {
    s.chars()
     .filter(|c| !matches!(c, '\u{200E}'|'\u{200F}'|'\u{202A}'..='\u{202E}'|'\u{0640}'))
     .map(|c| match c { '\u{064A}'|'\u{0649}' => '\u{06CC}', '\u{0643}' => '\u{06A9}', c => c })
     .collect()
}
```
برای داده‌های موجود، یک مهاجرت `UPDATE accounts SET name = replace(replace(name,'ي','ی'),'ك','ک')` بزنید. اسناد دائمی با تریگر قفل‌اند، پس برای شرح آن‌ها یک تابع SQLite به نام `fa_norm` با `create_scalar_function` ثبت کنید و در `LIKE` استفاده کنید. فیچر `functions` را به rusqlite اضافه کنید.

### اولویت متوسط

**۵. رمز پشتیبان `.hacc` نرمال‌سازی نمی‌شود**
- **محل:** `db/portable.rs`، تابع `derive_key` (از `password.as_bytes()` مستقیم استفاده می‌کند).
- **مشکل:** رمزی که با ارقام فارسی یا «ی» یک کیبورد ساخته شده، روی کیبورد یا سیستم دیگر کدپوینت متفاوتی می‌دهد و باز نمی‌شود. این برای انتقال پشتیبان به دستگاه دوم خطرناک است.
- **راهکار:** رمز را قبل از Argon2 با NFKC و تبدیل ارقام و حروف نرمال کنید. چون پشتیبان‌های قبلی با بایت خام ساخته شده‌اند، هنگام بازگشایی اول بایت خام و بعد نسخهٔ نرمال را امتحان کنید. نسخهٔ جدید فایل را با یک پرچم در هدر مشخص کنید.
- **نکتهٔ جانبی:** `key.fill(0)` ممکن است توسط کامپایلر حذف شود. از `zeroize` و فیچر `zeroize` برای `aes-gcm` استفاده کنید.

**۶. پشتیبان خودکار وجود ندارد، ولی مستند ادعا می‌کند**
- **مشکل:** `Docs/Data-Protection-and-Release-Policy.md` از «پشتیبان‌های دستی و خودکار» می‌گوید، ولی در کد فقط پشتیبان دستی و snapshot قبل از حذف گروهی و مهاجرت سطح ۴ هست. همهٔ پشتیبان‌ها هم در `backups/` کنار دیتابیس و روی همان دیسک‌اند.
- **راهکار:** پشتیبان خودکار هنگام بستن برنامه یا اولین اجرای روز، یک مسیر خارجی اختیاری (فلش یا پوشهٔ همگام‌شده)، نمایش تاریخ آخرین پشتیبان در نوار وضعیت و هشدار اگر از N روز گذشته باشد. یا مستند را اصلاح کنید.

**۷. `save_report_html` دستور sync است**
- **محل:** `commands/print.rs`.
- **مشکل:** فقط چهار دستور بدون `async` مانده‌اند (`open_path`، `get_print_doc`، `save_report_html`، `take_voucher_request`). `save_report_html` روی ترد اصلی `rfd::FileDialog::save_file()` بلوکه را صدا می‌زند و فایل می‌نویسد، پس همهٔ پنجره‌ها هنگام دیالوگ قفل می‌شوند.
- **راهکار:** `#[tauri::command(async)]`. پارامتر `html` در بک‌اند نادیده گرفته می‌شود؛ اگر UI هنوز آن را می‌فرستد، حذفش کنید تا چند مگابایت بی‌دلیل از IPC رد نشود. همچنین اگر کاربر «x.htm» بزند، فایل «x.htm.html» می‌شود.

**۸. دسترسی دستورها فقط با چک دستی برچسب پنجره کنترل می‌شود**
- **محل:** `build.rs` و `capabilities/default.json`.
- **مشکل:** `tauri_build::build()` ساده است و هیچ ACL سطح دستور تعریف نشده. هر ۸۷ دستور برای همهٔ پنجره‌ها در دسترس‌اند و محافظت فقط به حدود ۹۸ فراخوانی `require_window` تکیه دارد. دستور جدیدی که این چک را فراموش کند، برای همه باز است.
- **راهکار:** با `AppManifest::new().commands(&[...])` در `build.rs` دستورها را به مجوز تبدیل کنید و برای هر پنجره یک capability جدا بنویسید.
- **CSP:** `base-uri` و `form-action` به `default-src` برنمی‌گردند. اضافه کنید: `base-uri 'none'; form-action 'none'; object-src 'none'`. اگر ممکن است `style-src 'unsafe-inline'` را هم حذف کنید.

### اولویت پایین

- **۹. `create_private_file`** فقط روی Unix مجوز `0o600` می‌گذارد، ولی کامنتش ادعای «فقط کاربر جاری» می‌کند. روی ویندوز به ارث‌بری ACL پوشهٔ `%APPDATA%` تکیه دارد (در عمل کافی است). برای تضمین پاک‌شدن فایل متن ساده حتی هنگام کرش، از `custom_flags(FILE_FLAG_DELETE_ON_CLOSE)` در `OpenOptionsExt` ویندوز استفاده کنید.
- **۱۰. `replace_file`** دو `rename` پشت‌سرهم است و بین آن‌ها مقصد وجود ندارد. در ویندوز یک `std::fs::rename` ساده فایل مقصد را جایگزین می‌کند.
- **۱۱. `seed_default_*`** هر بار که شمارش جدول صفر باشد اجرا می‌شود؛ اگر کاربر همهٔ حساب‌ها را پاک کرده باشد، با اجرای بعدی نمودار پیش‌فرض برمی‌گردد. یک پرچم `seeded` در `app_meta` بگذارید.
- **۱۲. `panic = "abort"`:** در release هیچ پیامی از کرش نمی‌ماند، و کامنت‌های «بازیابی از mutex مسموم» در آن حالت بی‌اثرند. یک `panic::set_hook` بگذارید که در فایل لاگ بنویسد.
- **۱۳. CI:**
  - `permissions:` تعریف نشده است؛ `contents: read` را در سطح workflow بگذارید.
  - اکشن‌ها با tag (مثل `@v7`) به‌جای SHA قفل شده‌اند.
  - `dtolnay/rust-toolchain@stable` با `rust-version = "1.88"` هماهنگ نیست؛ یک job با 1.88 اضافه کنید.
  - `timeout-minutes` و `concurrency` ندارد.
  - Dependabot هم اضافه کنید.
- **۱۴. فرانت‌اند:** `account-definition.js` (۲۰۴۴ خط) همهٔ ردیف‌ها را با `innerHTML` و بدون virtual scroll رندر می‌کند (P2-08 شما). حدود ۱۶ کیلوبایت فایل `eslint.ui-globals.js` نشان می‌دهد صفحه‌ها از global مشترک استفاده می‌کنند؛ مهاجرت تدریجی به ES modules تفکیک فایل‌های بزرگ را (P2-07) راحت‌تر می‌کند.
