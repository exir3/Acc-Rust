# بسته اصلاحات فاز دوم — تفکیک حساب پایه و تفصیلی ۱

## دامنه اصلاحات

این بسته برای پروژه `Acc-Rust` و براساس ساختار موجود در فایل ZIP ارسالی تهیه شده است. هدف اصلی، هم‌راستا کردن مدل ثبت سند با مدل فعلی WebApp است:

- هر ردیف سند یک حساب پایه از سطح ۱ (کل) یا سطح ۲ (معین) دارد.
- تفصیلی ۱ از سطح ۳، اختیاری و در فیلد مستقل نگهداری می‌شود.
- انتخاب تفصیلی فقط برای حساب معین و فقط از فرزندان مستقیم همان معین مجاز است.
- ثبت مستقیم روی حساب کل یا معین مجاز است؛ وجود زیرحساب، قابلیت ثبت حساب پایه را از بین نمی‌برد.
- سطح ۴ یا بالاتر به‌صورت خودکار حذف یا تبدیل نمی‌شود؛ مهاجرت در صورت وجود چنین حساب‌هایی متوقف می‌شود تا سوابق تعیین تکلیف شوند.

علاوه بر فرم سند، ذخیره/بازیابی، اعتبارسنجی، انتقال و جابه‌جایی ردیف‌ها، ورود و خروج Excel، گزارش روزنامه، دفترکل، تراز آزمایشی، فعالیت حساب، حذف/تغییر ساختار حساب و اعتبارسنجی پشتیبان نیز اصلاح شده‌اند.

## روش اعمال پیشنهادی

1. از کل پوشه پروژه و به‌خصوص فایل‌های پایگاه داده نسخه پشتیبان تهیه کنید.
2. برنامه را ببندید.
3. محتوای پوشه `changed-files` را با حفظ مسیرها روی ریشه پروژه خود کپی و فایل‌های موجود را جایگزین کنید. این روش برای محیط ویندوز و حفظ پایان‌خط فایل‌ها پیشنهاد می‌شود.
4. پروژه را در VS Code باز کنید و از ریشه پروژه دستورات زیر را اجرا کنید:

```powershell
cargo fmt --all
cargo test
cargo clippy --all-targets --all-features -- -D warnings
npm run check:js
```

5. برنامه را اجرا کنید و سناریوهای بخش «آزمون دستی» در انتهای این فایل را بررسی کنید.
6. پس از موفقیت تست‌ها و تأیید رفتار برنامه، تغییرات را در مخزن خودتان commit و push کنید.

فایل `PATCH.diff` برای مشاهده یا اعمال patch در Git نیز ضمیمه شده است؛ در صورت اختلاف پایان‌خط‌ها در ویندوز، روش جایگزینی مستقیم `changed-files` مطمئن‌تر است.

## مهاجرت پایگاه داده نسخه ۵

نسخه schema به ۵ می‌رسد. ردیف‌های قدیمی که کد حساب سطح ۳ را مستقیماً در `account_code` ذخیره کرده‌اند، به ساختار زیر تبدیل می‌شوند:

- `account_id`: شناسه حساب پایه (معین والد)
- `account_code`: کد همان حساب پایه، برای سازگاری با بخش‌هایی که هنوز از کد استفاده می‌کنند
- `detail1_code`: کد تفصیلی سطح ۳

تبدیل در تراکنش انجام می‌شود. پیش از ثبت نسخه جدید، شمار ردیف‌ها و جمع بدهکار/بستانکار هر سند مقایسه می‌شود. اگر حساب سطح ۴ یا بالاتر، ارجاع یتیم یا تفصیلی با والد/گروه نامعتبر وجود داشته باشد، مهاجرت با پیام قابل‌فهم متوقف می‌شود و تراکنش rollback خواهد شد. در چنین وضعی دیتابیس را دستی حذف یا تغییر ندهید؛ ابتدا backup بگیرید و ساختار قدیمی را بررسی کنید.

فایل‌های پشتیبان نسخه ۴ نیز به‌عنوان منبع مهاجرت پذیرفته می‌شوند. Restore ابتدا نسخهٔ ایمن دیتابیس فعال را نگه می‌دارد و در صورت شکست مهاجرت، تلاش بازیابی را rollback می‌کند.

## فایل‌ها

- `changed-files/`: جایگزین مستقیم ۲۹ فایل اصلاح‌شده
- `PATCH.diff`: اختلاف متنی بین نسخه ZIP مبنا و نسخه اصلاح‌شده
- `CHANGELOG-FA.md`: شرح تغییرات فنی
- `VALIDATION-FA.md`: وضعیت آزمون‌ها و محدودیت‌های محیط اجرا
- `test-log.txt`: خروجی واقعی دو بررسی قابل اجرا در این محیط

هیچ commit یا push به GitHub انجام نشده است.
