# گزارش اعتبارسنجی فاز دوم

تاریخ بررسی: ۴ نوامبر ۲۰۲۶

## آزمون‌های اجراشده و موفق

1. `npm run check:js` — موفق؛ هر ۴۲ فایل JavaScript از نظر syntax بررسی شدند.
2. شبیه‌سازی مهاجرت SQLite روی schema واقعی پروژه — موفق:
   - ردیف دارای کد تفصیلی سطح ۳ به حساب پایه + تفصیلی ۱ تبدیل شد.
   - تعداد ردیف‌ها و جمع بدهکار/بستانکار بدون تغییر ماند.
   - ثبت تفصیلی برای حساب کل، تفصیلی متعلق به معین دیگر و account_id خالی توسط guardها رد شد.
   - مهاجرت با وجود سطح ۴ به‌صورت اتمیک متوقف شد؛ نسخه، schema و داده‌ها ثابت ماندند.
   - `PRAGMA foreign_key_check` نتیجه خالی داد.
   - تجمیع مؤثر، مبلغ مستقیم حساب پایه و مبلغ تفصیلی را در کد مربوط خود و فقط یک‌بار ثبت کرد.
3. `git diff --check` با درنظرگرفتن پایان‌خط CRLF — موفق؛ whitespace جدید نامعتبر گزارش نشد.
4. جستجوی ایستا برای شرط پیشوندی فرزند/والد در کد Rust — هیچ موردی باقی نماند.
5. `git apply --check PATCH.diff` روی نسخه پاک مبنا — موفق؛ پس از اعمال patch، محتوای هر ۲۹ فایل دقیقاً با فایل‌های جایگزین بسته یکسان بود.

## آزمون‌هایی که در این محیط قابل اجرا نبودند

ابزارهای `cargo`، `rustc` و `rustfmt` در محیط اجرای فعلی نصب نیستند. بنابراین **کامپایل Rust، `cargo fmt`، `cargo test` و `cargo clippy` اجرا نشده‌اند** و نباید این بسته را از این نظر «کامپایل‌شده/تست کامل» تلقی کرد. دستورات لازم در `README-FA.md` آمده‌اند و باید در محیط توسعه ویندوز اجرا شوند.

همچنین رفتار تعاملی فرم سند، ورود فایل‌های واقعی Excel، گزارش‌های چاپی و restore روی دیتابیس واقعی در رابط دسکتاپ هنوز نیازمند آزمون کاربر است.

## نکته مهم در مهاجرت

اگر دیتابیس فعلی هر حساب سطح ۴ یا بالاتر داشته باشد، اجرای مهاجرت نسخه ۵ عمداً متوقف می‌شود؛ هیچ داده‌ای حذف نمی‌شود. پیش از به‌روزرسانی از دیتابیس backup تهیه کنید و خطای مهاجرت را به‌عنوان هشدار حفاظت از سابقه در نظر بگیرید، نه خطایی که باید با حذف دستی داده دور زده شود.
