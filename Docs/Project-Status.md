# وضعیت پروژه Acc-Rust

**آخرین به‌روزرسانی:** ۷ نوامبر ۲۰۲۶  
**مبنای بررسی:** کد محلی در commit `3c34226` به‌همراه تغییرات محلی اعتبارسنجی ممیزی  
**وضعیت انتشار:** خروجی صورت‌های مالی تا امضای حسابدار مستقل و سبز شدن CI روی commit جدید، «نیازمند تأیید» است.

این سند تنها مرجع وضعیت پروژه است و جایگزین گزارش‌های فنی پراکندهٔ قبلی (بررسی‌های ۶ و ۷
نوامبر ۲۰۲۶) می‌شود. آن گزارش‌ها در همین سند ادغام شده‌اند و نسخهٔ تاریخی آن‌ها فقط در
تاریخچهٔ گیت (commit `5ba10b2` و پیش از آن) باقی است.

نکتهٔ P1-03: resolver فعلی برای هر حساب یک سرفصل معتبر انتخاب می‌کند و حالت
`UNCLASSIFIED` از مسیر معمولی ساخت حساب قابل ایجاد نیست. اصلاح انجام‌شده
دفاعی است و مانده‌های بدون سرفصلِ دادهٔ قدیمی/واردشده یا نتیجهٔ تغییر آیندهٔ
resolver را از حدس خارج می‌کند. آزمون‌های واحد سازندهٔ گزارش‌ها این رفتار را
پوشش می‌دهند.

P1-05 همچنان باز است و بدون تأیید مستقل حسابدار/حسابرس بسته نمی‌شود.

### خلاصهٔ راهکارهای موارد باز

- **P1-03:** پس از تثبیت طبقه‌بندی و چرخهٔ بستن، گزارش‌های WebApp به ترتیب جریان
  وجوه نقد، تغییرات حقوق مالکانه، بهای تمام‌شده و تخصیص سود منتقل شوند؛ همه از یک
  قرارداد مشترک `ReportScope`، تاریخ و واحد مبلغ استفاده کنند.
- **P2-01:** یک pool کوچک اتصال خواندن با WAL، `query_only` و `busy_timeout` ایجاد
  شود؛ هنگام restore/backup خواننده‌ها متوقف و پس از آن بازسازی شوند.
- **P2-02:** Virtual Scrolling برای تراز آزمایشی، اعمال فیلترهای سنگین در بک‌اند و
  حفظ انتخاب/فوکوس بر اساس کد حساب.
- **P2-03:** خواندن مرحله‌ای Excel، اعتبارسنجی و staging، گزارش خطای هر ردیف و
  commit نهایی اتمیک با حفظ progress و cancel.
- **P2-04:** ستون نرمال‌شده یا FTS5 برای جستجوی فارسی/عربی و keyset pagination با
  کلید پایدار `(date, number, id)`.
- **P2-06:** تعریف صریح DTO تاریخ/مبلغ/شناسه و آزمون round-trip برای تاریخ کبیسه،
  ارقام فارسی/عربی و مبلغ بزرگ.
- **P3-04:** تفکیک فایل‌های بزرگ UI به state، validation، data-access، rendering و
  event binding، بدون انتقال منطق مالی از Rust به JavaScript.
