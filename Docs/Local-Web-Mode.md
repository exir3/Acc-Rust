# حالت وب محلی

نسخهٔ وب محلی برای اجرای همان رابط کاربری حسابداری در مرورگر روی همین دستگاه
است. این حالت یک سرور HTTP کوچک با Rust/Axum روی `127.0.0.1` بالا می‌آورد و
همان پایگاه دادهٔ SQLite و همان منطق حسابداری نسخهٔ دسکتاپ را استفاده می‌کند.
هدف آن میزبانی روی شبکه یا اینترنت نیست؛ هیچ احراز هویتی هم ندارد و فقط برای
همین Windows session طراحی شده است.

## دامنهٔ فعلی

فاز ۱ (برش خواندنی و سال مالی)، فاز ۲ (فرم سند)، فاز ۳ (گزارش‌های اصلی و
پیش‌نمایش چاپ)، فاز ۴ (صورت‌های مالی تکمیلی)، فاز ۵ (پشتیبان‌گیری و بازیابی) و
فاز ۶ (بستن سال مالی و انتقال مانده) فعال است:

- خواندن تنظیمات شرکت
- خواندن گروه‌های حساب، حساب‌ها و کاتالوگ سرفصل‌های صورت‌های مالی
- خواندن سال‌های مالی و ساخت/ویرایش/حذف سال مالی و تغییر وضعیت آن
- پیش‌نمایش بستن سال مالی، ذخیرهٔ نقش حساب‌های بستن، اجرای بستن و برگشت بستن
  با ثبت دلیل
- پیش‌نمایش انتقال مانده به سال بعد و ایجاد سند افتتاحیه در سال مقصد
- خواندن تعداد اسناد، لیست اسناد و تراز آزمایشی
- بازکردن پنجره‌های تراز آزمایشی، لیست اسناد، گروه حساب‌ها و تعریف حساب‌ها
  به‌صورت تب/پنجرهٔ مرورگر
- بازکردن فرم سند از منوی برنامه یا لیست اسناد
- ثبت و ویرایش سند، دائمی‌کردن سند موقت و حذف سند موقت
- کپی یا انتقال ردیف‌های سند بین اسناد
- ساخت سریع حساب از داخل فرم سند
- صفحات دفتر روزنامه، دفتر کل، صورت سود و زیان و ترازنامه
- صفحات تکمیلی صورت تغییرات حقوق مالکانه، بهای تمام‌شدهٔ کالای فروش‌رفته،
  تخصیص سود و جریان‌های نقدی (روش غیرمستقیم)
- پیش‌نمایش چاپ سند و همهٔ این گزارش‌ها در تب مرورگر، با چاپ/PDF از پنجرهٔ
  چاپ مرورگر و ذخیرهٔ نسخهٔ HTML در پوشهٔ دانلودهای مرورگر
- پشتیبان‌گیری ساده (SQLite) و رمزنگاری‌شده (`.hacc`) با دانلود از مرورگر
- بازیابی پشتیبان با انتخاب فایل در مرورگر، بررسی هش و ساخت نسخهٔ ایمنی خودکار
  پیش از جایگزینی پایگاه داده
- خواندن تاریخچهٔ حسابرسی در صفحهٔ تنظیمات

سایر فرمان‌های Tauri (Excel، ویرایش تنظیمات و...) در این مرحله پاسخ «هنوز
پشتیبانی نمی‌شود» می‌دهند. دکمه‌های مربوط به آن‌ها در رابط کاربری ممکن است دیده
شوند، اما عمل نمی‌کنند.

چند محدودیت مرورگری نیز وجود دارد:

- اگر مرورگر پنجره‌های بازشو را مسدود کند، پنجرهٔ درخواستی (مثل تراز آزمایشی)
  در همان تب جاری باز می‌شود. برای این حالت، اجازهٔ بازشدن پنجره برای
  `127.0.0.1` را در مرورگر فعال کنید.
- بستن تب با دکمهٔ خود مرورگر، محافظ «تغییرات ذخیره‌نشده» را اجرا نمی‌کند.
  فرم‌های دارای دادهٔ ذخیره‌نشده را با دکمهٔ بستن داخل برنامه ببندید.
- فرم سند در تبی با نام `voucher` باز می‌شود. اگر این تب باز باشد، درخواست
  بازکردن سند دیگر روی همان تب اعمال می‌شود و تب دوباره بارگذاری نمی‌شود تا
  دادهٔ ذخیره‌نشده از دست نرود.
- پیش‌نمایش‌های چاپ در یک تب مشترک با نام `print-preview` باز می‌شوند؛ درخواست
  جدید همان تب را به گزارش تازه منتقل می‌کند.
- چاپ از پنجرهٔ چاپ مرورگر انجام می‌شود و «ذخیره HTML» به‌جای پنجرهٔ ذخیرهٔ
  ویندوز، فایل را در پوشهٔ دانلودهای مرورگر می‌نویسد.
- پشتیبان‌ها هم در پوشهٔ `backups` کنار پایگاه داده ساخته می‌شوند و هم از
  مرورگر دانلود می‌شوند. بازیابی، فایل انتخابی را حداکثر ۵۱۲ مگابایت می‌پذیرد
  و آن را موقتاً در `restore-uploads` نگه می‌دارد؛ فایل پس از بازیابی یا با
  گذشت ۱۵ دقیقه پاک می‌شود.

## اجرا

```bat
npm run dev:web
```

یا مستقیم:

```bat
cargo run --manifest-path src-tauri/Cargo.toml --features web --bin hesabdari-web
```

سرور روی `http://127.0.0.1:4174/` بالا می‌آید و به‌طور پیش‌فرض مرورگر را باز
می‌کند. برای اجرای بدون بازکردن مرورگر:

```bat
set HESABDARI_NO_OPEN=1
npm run dev:web
```

در حالت توسعه، پوشهٔ `ui` به‌طور خودکار پیدا می‌شود. تغییر فایل‌های JavaScript
یا CSS نیاز به restart ندارد؛ صفحه را در مرورگر دوباره بارگذاری کنید. تغییر
کد Rust نیاز به توقف و اجرای دوبارهٔ دستور دارد.

## تنظیمات محیطی

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `HESABDARI_DATA_DIR` | `%APPDATA%\ir.hesabdari.software` | پوشهٔ پایگاه داده؛ باید مسیر مطلق باشد |
| `HESABDARI_WEB_PORT` | `4174` | پورت loopback؛ صفر مجاز نیست |
| `HESABDARI_UI_DIR` | پوشهٔ `ui` کنار پروژه/فایل اجرایی | مسیر پوشهٔ رابط کاربری |
| `HESABDARI_NO_OPEN` | تنظیم‌نشده | هر مقدار غیرخالی از بازشدن خودکار مرورگر جلوگیری می‌کند |

پوشهٔ پیش‌فرض داده‌ها همان پوشهٔ نسخهٔ دسکتاپ است. بنابراین سال‌های مالی،
حساب‌ها و اسناد بین دو حالت مشترک‌اند. **نسخهٔ دسکتاپ و نسخهٔ وب را هم‌زمان
روی یک فایل پایگاه داده اجرا نکنید.** هر دو یک اتصال نوشتن دارند و رفتار
قفل‌شدن SQLite در این حالت قابل پیش‌بینی نیست؛ ابتدا یکی را ببندید و سپس
دیگری را باز کنید.

## ساخت

```bat
npm run build:web
```

خروجی در `src-tauri/target/release/hesabdari-web.exe` ساخته می‌شود. برای اجرای
قابل حمل، پوشهٔ `ui` را کنار فایل اجرایی قرار دهید (یا `HESABDARI_UI_DIR` را
تنظیم کنید) و سپس:

```bat
hesabdari-web.exe
```

## امنیت

- سرور فقط به `127.0.0.1` گوش می‌دهد؛ از دستگاه‌های دیگر قابل دسترسی نیست.
- هیچ رمز یا نشست کاربری وجود ندارد؛ دسترسی به مرورگر همین دستگاه به معنی
  دسترسی به داده‌های حسابداری است.
- درخواست‌های دستور به شکل JSON و از همان origin ارسال می‌شوند. سرور CORS
  باز نمی‌کند.
- دانلود پشتیبان و بارگذاری فایل بازیابی فقط با توکن‌های کوتاه‌عمر انجام
  می‌شود؛ مسیر فایل از مرورگر گرفته نمی‌شود. بازیابی پیش از هر تغییر، یک نسخهٔ
  ایمنی خودکار می‌سازد و فایل را دوباره با هش بررسی می‌کند.
- پشتیبان رمزنگاری‌شده فقط با رمز خودش بازیابی می‌شود؛ رمز در سرور ذخیره
  نمی‌شود.

## آزمون

```bat
cargo test --manifest-path src-tauri/Cargo.toml --features web --lib web::tests
npm run check:js
npm run lint:js
```

آزمون‌های `web::tests` با پایگاه دادهٔ in-memory همان قواعد ذخیره‌سازی و
پاسخ‌دهی فرمان‌ها را بررسی می‌کنند و به شبکه یا فایل کاربر دست نمی‌زنند؛
آزمون‌های پشتیبان‌گیری از یک پوشهٔ موقت استفاده می‌کنند.
آزمون‌های فاز ۲ چرخهٔ ثبت، خواندن، ویرایش، دائمی‌کردن، انتقال ردیف و حذف
سند و همچنین ساخت سریع حساب را پوشش می‌دهند. آزمون‌های فاز ۳ گزارش‌های
روزنامه/دفتر کل/سود و زیان/ترازنامه و ذخیره‌سازی سند چاپ برای تب پیش‌نمایش را
بررسی می‌کنند. آزمون‌های فاز ۴ خواندن چهار صورت تکمیلی و ساخت پیش‌نمایش چاپ
آن‌ها را از همان لایهٔ گزارش دسکتاپ بررسی می‌کنند. آزمون‌های فاز ۵ ساخت
پشتیبان ساده و رمزنگاری‌شده، دانلود توکن‌دار، بازیابی با هش و رمز، رد کردن
فایل منقضی و محدودیت پنجره را پوشش می‌دهند. آزمون‌های فاز ۶ تغییر وضعیت و حذف
سال مالی، پیش‌نمایش و اجرای بستن، برگشت بستن و انتقال مانده به سال بعد را
بررسی می‌کنند.
