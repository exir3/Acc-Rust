# مستندات Acc-Rust

این پوشه مستندات زنده و آرشیو بررسی‌های تاریخی را نگه می‌دارد. مرجع وضعیت
پروژه [`Project-Status.md`](Project-Status.md) است؛ گزارش‌های بررسی، سند
نقطه‌ای (point-in-time) هستند و جای وضعیت جاری را نمی‌گیرند.

## مستندات جاری

| سند | نقش | مخاطب اصلی |
| --- | --- | --- |
| [`Project-Status.md`](Project-Status.md) | تنها مرجع وضعیت پروژه، کارهای انجام‌شده، یافته‌های باز و موانع انتشار | تیم فنی و مدیریت |
| [`Account-Code-Policy.md`](Account-Code-Policy.md) | سیاست الزامی کد و گروه حساب؛ مبنای فرم، اعتبارسنجی Rust و Excel | توسعه‌دهنده |
| [`Accounting-Report-Signoff.md`](Accounting-Report-Signoff.md) | کنترل تأیید مستقل گزارش‌های مالی و gate انتشار رسمی؛ مسیر این فایل در CI ثابت است | حسابدار/حسابرس و انتشار |
| [`Data-Protection-and-Release-Policy.md`](Data-Protection-and-Release-Policy.md) | سیاست پشتیبان‌گیری، رمزنگاری، ممیزی وابستگی و امضای انتشار | تیم فنی و استقرار |

## آرشیو بررسی‌ها

گزارش‌های زیر سند تاریخی‌اند و عمداً به‌روزرسانی نمی‌شوند:

| سند | تاریخ | موضوع |
| --- | --- | --- |
| [`Archive/Acc-Rust-Review-fa.md`](Archive/Acc-Rust-Review-fa.md) | ۸ نوامبر ۲۰۲۶ | آخرین گزارش جامع فنی، معماری و حسابداری؛ مرجع تفصیلی یافته‌های همین تاریخ |
| [`Archive/Acc-Rust-Frontend-UX-Review-fa.md`](Archive/Acc-Rust-Frontend-UX-Review-fa.md) | ۸ نوامبر ۲۰۲۶ | بررسی فرانت‌اند، کاربردپذیری و تجربه کاربری |

بررسی‌های قدیمی‌تری که با گزارش جامع ۸ نوامبر جایگزین شده‌اند (ممیزی فنی ۷
نوامبر، گزارش اجرایی اولیه و `review-3`) از پوشه حذف شده‌اند تا فقط یک مرجع
وضعیت و دو گزارش مرجع (فنی و تجربه کاربری) باقی بماند. متن آن‌ها از تاریخچه Git
قابل بازیابی است.

## قواعد نگهداری

- وضعیت جاری فقط در `Project-Status.md` به‌روزرسانی می‌شود؛ گزارش بررسی جدید
  جای آن را نمی‌گیرد.
- گزارش‌های بررسی پس از پایان کار در `Archive/` نگهداری می‌شوند و فقط یافته‌های
  باز آن‌ها به `Project-Status.md` منتقل می‌شود.
- سیاست‌های عملیاتی (کد حساب، حفاظت داده و sign-off) جدا از گزارش‌ها می‌مانند،
  چون کد، CI یا فرایند انتشار مستقیماً به آن‌ها ارجاع می‌دهند.
